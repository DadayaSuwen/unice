# 官网绝对化用语合规整改 — 设计文档

- 日期：2026-08-16
- 状态：已确认，转实现
- 触发：针对官网 www.uniche.cn 的举报，指控宣传文案多次使用「一流」等绝对化用语，违反《广告法》第九条第三项、《反不正当竞争法》第八条。

## 背景与目标

官网内容已后台化（Payload CMS + PostgreSQL），线上展示内容主要来自数据库；`app/lib/globals.ts` 中的 `FALLBACK_*` 仅在数据库字段缺失/读取失败时兜底。举报所述「一流」等绝对化用语同时存在于：

1. 代码兜底 `app/lib/globals.ts`
2. seed 源 `payload/seed.ts`
3. 线上数据库（由 seed 灌入）

目标：将以上三处的绝对化用语统一替换为合规表述，保留可核实的事实陈述；产出整改记录文档作为证据；通过 git 提交留下审计线索。

## 整改脚本设计（scripts/remediate-absolute-claims.ts）

- 运行方式：`tsx -r dotenv/config scripts/remediate-absolute-claims.ts [--apply]`，与 seed.ts 同一套 `getPayload({ config })`。
- **默认 dry-run**：遍历全部 Globals + 集合（hero-banners、news、products、careers…）全部实例；递归扫描字符串 / 文本数组 / 富文本 Lexical 文本节点（`{ type:'text', text }`）；按短语替换表（长度降序）应用；输出「旧→新」逐条报告与命中计数；不写库。
- `--apply`：执行写回（`updateGlobal` / `update`），随后回读校验：核心禁用词清单仍命中 → 打印并 exit 1。
- 边界：仅替换命中词所在位置，保留字段内其他内容与结构，避免覆盖后台人工编辑。
- 安全流程：先 dry-run 报告给用户确认 → 再 `--apply`。

## 验证
